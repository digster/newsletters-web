# 2026-09-02 — Front-matter quote escaping

## Problem

Newsletter listing headers rendered escaped quotes: `Why I quit \"The Strive\"`. The user
noticed it was inconsistent — some rows escaped, some not.

## Root cause

`parse_front_matter` in `scripts/build_site.py` matched double-quoted YAML scalars with
`"((?:[^"\\]|\\.)*)"`. That pattern *tolerates* escape sequences (so a `\"` does not end
the scalar early) but the captured text was written to the manifest verbatim — the
backslashes were never resolved.

The upstream ingestor quotes every value, so this fired on every subject containing a
quote. Not random at all:

- 396 subjects (873 quote pairs)
- 3,152 `from:` values (RFC 5322 quotes display names containing `@`, `.`, etc.)

The apparent inconsistency came from the two-source row layout: the subject comes from the
build-time manifest (escaped), while the grey preview beside it is extracted at runtime
from the email HTML via `DOMParser` (clean). Same words, two renderings, one row.

## Fix

- Added `unescape_double_quoted()` — resolves standard YAML double-quote escapes
  (`\"`, `\\`, `\n`, `\t`, `\xNN`, `\uNNNN`, `\UNNNNNNNN`, and the YAML-specific
  `\N \_ \L \P \e \a \v \0`). Unknown or malformed sequences pass through with the
  backslash intact rather than silently dropping a character.
- Fixed the single-quoted branch of `YAML_LINE_RE`: single-quoted YAML escapes a quote by
  doubling it (`''`), and treats backslashes literally. The old pattern wrongly applied
  double-quote rules to it.
- 13 new tests in `scripts/test_build_site.py` (`TestParseFrontMatter`). Suite: 61 pass.
- Rebuilt the site. Diff was exactly 5 files: the manifest, two generated Quincy pages
  whose `<title>` held escapes, and the two scripts. The 16,738 verbatim-copied emails
  came out byte-identical, confirming the rebuild was non-destructive.

## Verified

- All 3,528 manifest changes proved to be quote-unescaping only; `newsletter`, `date` and
  `file` fields byte-identical, no records added or removed.
- Browser check at `localhost:8123`: `Why I quit "The Strive"` and `"Collaboration" is
  bullshit.` render correctly in the listing header, the viewer chrome and the `<title>`,
  and now match their body previews.

## Known residue (intentional)

16 Psmith records keep a backslash in `from`: their display name genuinely contains
quotes, so it is encoded twice (RFC 5322, then YAML). Unescaping the YAML layer correctly
leaves the RFC 5322 layer in place. `from` is not rendered anywhere in the UI. Decoding
mail display names is a separate concern and was left out of scope.
