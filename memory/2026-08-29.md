# 2026-08-29 — Markdown Fallback for HTML-less Emails

## Problem

`scripts/build_site.py` silently dropped any source email with no `.html` file:

```python
if not html_files:
    continue
```

Two flaws. The `continue` fired *before* the front-matter parse, even though the `.md` file
had already been located one line earlier — so subject/from/date were always recoverable.
And nothing logged it: the `skipped` counter only tracked front-matter *exceptions*.

Measured: 16,989 source email directories, **400 with no `.html`**, all in `Quincy`, all
carrying both a `.md` and a `.txt`. The manifest showed `Quincy: count 4` with a date range
of a single day — 99% of a nine-year newsletter was invisible.

Content analysis of the 400 bodies: 100% had ordered-list items and bare URLs, 58% had `-`
bullets, and none had headings, `[text](url)` links, bold, italics or code. They are
plain-text bodies the upstream ingestor wrote into `.md` when trafilatura returned nothing.

## Changes

**`scripts/build_site.py`**

- Unified the two independent tree walks. `collect_emails()` now returns records carrying
  internal `_source` / `_rel` keys, and the old `copy_html_emails()` became
  `write_emails(records, output_dir)`, which consumes that list instead of re-walking.
  This turns "every manifest path exists on disk" from a coincidence into an invariant.
- `MANIFEST_KEYS` + `manifest_record()` project records down to the frozen six-key public
  schema, so internal keys cannot leak into `data/index.json`. Verified: 0 occurrences.
- Fallback: `.html` if present, else the `.md` body, else skip with a warning (currently
  zero). Front-matter parsing moved above the branch so metadata survives either path.
- `render_markdown()` / `render_inline()` / `render_email_page()` — a small stdlib
  markdown→HTML converter. Escape-first; code spans and anchors parked behind NUL
  placeholders; `http:`/`https:`/`mailto:` scheme allowlist.
- Added `sorted()` to the `.html` / `.md` globs. 11 directories hold >1 `.html` and one
  holds >1 `.md`; `glob` returns filesystem order, so the `[0]` pick was nondeterministic.
- Logging: per-newsletter counts now report how many were rendered from markdown.

**`scripts/test_build_site.py`** — new, 43 stdlib `unittest` tests (the repo had none).

**Docs** — `ARCHITECTURE.md` (data-flow diagram, LFS counts, new "Markdown Fallback"
subsection), `README.md`, `PROMPT.md`.

## Two bugs the process caught

1. **Loose lists.** First build produced three separate `<ol>` blocks rendering "1. 1. 1."
   — every one of these bodies separates numbered items with a blank line, and the blank
   line was flushing the list. Fixed so a blank line defers the close; non-list content is
   what actually closes a list. `<ol start="N">` preserves an explicit starting number.
2. **Dead state.** The first version of that fix introduced a `blank_pending` flag that was
   assigned in four places and never read — the deferral works purely by *not* flushing.
   Removed it.

## Result

`total_emails` 16,589 → **16,989**. `Quincy` 4 → **404**, date range `2021-08-19` only →
`2017-07-13 … 2026-08-21`. 400 generated pages, ~2 MB total, automatically Git-LFS tracked
by the existing `emails/**/*.html` rule.

Verified in a browser: viewer iframe renders correct 1/2/3 numbering with clickable links;
inline previews and the hover tooltip work against generated pages and do *not* start with
a duplicated subject (which is why the generated pages carry no header); dark mode shows
dark chrome with a light body, matching every copied email.

## Notes for next time

- `app.js` still exists as two byte-identical copies (root + `templates/`). Untouched here,
  because keeping the manifest schema frozen avoided any client change.
- A sign-off written as `- Quincy Larson` renders as a single-item bullet list. That is
  standard markdown behavior and is covered by an explicit test documenting the choice.
- `.txt` is never used as a body. Every HTML-less directory has a `.md`, so the chain is
  `.html → .md → skip`.
